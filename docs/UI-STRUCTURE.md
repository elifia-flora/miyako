详情面板内部的每一块叫**「模块」（section，`detail.modules` = 「显示模块」）**，
右键详情面板空白处可以按曲目单独开关，清单在 `App.vue` 的 `DETAIL_MODULES`：

> 附注 · 别名 · 情绪 · 拍号/速度 · 调性 · 制作/发行 · 作曲技法 · 乐器组合 · **体裁与结构** · 时间轴·段落 · 音源与录音版本（共 11 块）

**体裁与结构**（v0.56，2026-11-04）夹在「乐器组合」和「时间轴 · 段落」之间：
先说这是一部什么作品、按什么骨架长成，再往下才是逐段的时间轴。里面是**整曲一条**的抽象结论，
不做逐段曲式标注（分段已经有时间轴那一块，两处都标会变成两份要同步的真相）：
**体裁**（交响曲 / 弦乐四重奏 / 艺术歌曲…）、**曲式**（奏鸣曲式 / 回旋曲式 / 复三部曲式…）、
**作品编号**（No.1）、**作品号**（Op.2, No.1；没有的流行作品填 N/A，中文界面读作「不适用」）。
乐章子项则显示**子体裁**（小步舞曲 / Menuetto）与**速度术语**（小快板 / Allegretto）。
双击行内编辑，体裁类候选来自 `data/vocab/composition_type.json` 与 `form.json`。

> 赋格两边都收：体裁填「赋格」，曲式也可以填「赋格」（`fugue` / `fugue-form`）。
> 空值统一显示成灰字「未标注」—— 灰的是状态，不是禁用，照样能双击录入。
>
> 术语分工：**流派**答「用了哪一路写法」（古典 / 爵士 / 配乐），**体裁**答「这是一部什么作品」，
> **曲式**答「它按什么骨架长出来」。三者可以同时成立：古典（流派）交响曲（体裁）用奏鸣曲式（曲式）写成。
> 库里流派存词条 **name**（`Jazz`），体裁 / 曲式存 **id**（`symphony` / `sonata-form`）—— 后者要跟界面语言变。

**拍号 / 速度**这一行是 `4/4 · 130 BPM · 复拍子`。最后那个**拍号类型是算出来的**
（`shared/meter.js`），体系跟界面语言走：中文 → 中/苏/德奥（4/4 = 复拍子），
英文 → 英美（4/4 = simple meter）。两套结论相反的拍号（分子为 4 的那些）在文字**右边**
紧跟一个圆圈 **i**（`.mt-i`，11px、和字号同高 —— **不是右上角的上标**，
上标既难看清又难悬停），鼠标一悬停**立刻**弹出说明气泡。

垂直位置是**调过**的：`inline-flex` 的基线取的是内部那个「i」的基线，
`vertical-align: 0` 时圆圈会整体沉到基线以下（看起来「掉下来」）；现在用 `1.5px`
把它抬到与文字同一水平线（冒烟断言圆心中线与文字中线偏差 ≤1.5px）。

气泡（`.mt-pop`）有三条硬约定，缺一条就出问题：

1. **Teleport 到 body + `position: fixed`**，坐标由 `openMeterTip()` 现算。
   `.detail` 是 `overflow: auto`，气泡（268px）比右栏还宽，留在里面一定被裁掉半截；
   挂到 body 上也没人能把它压在曲目树下面。
2. **`v-if` 开关，不做任何过渡**（`transition` 必须是 `0s`）—— 悬停就要看到。
   也不用原生 `title`：那有约 1 秒延迟。
3. **用界面字体，不用等宽**：这段是整句中文说明，等宽读起来累。

## 2. 所有窗口（一个 index.html，靠 hash 分派）

| 中文名 | 英文名 | hash | 根组件 | 窗口标题 |
|---|---|---|---|---|
| 主窗口 | main window | （无） | `App.vue` | `music·atlas` |
| 歌词播报器 | Lyrics Player | `#lyrics` | `LyricsPlayer.vue` | 「歌词播报器」/「歌词播报器 — 曲名」（`win.lyricsTitle*`） |
| 桌面歌词 | Desktop lyrics | `#overlay` | `OverlayLyrics.vue` | 「桌面歌词」（`win.overlayTitle`） |
| 时间线窗口（独立） | Timeline | `#grid` | `GridStandalone.vue` | 「时间线 — music·atlas」（`win.gridTitle`） |
| 动态操作帮助 | Action help | `#help` | `ActionHelp.vue` | 「动态操作帮助」（`win.helpTitle`） |
| 封面大图 | cover viewer | `#image` | `ImageViewer.vue` | 取曲目名 / 「查看封面」 |

- **主窗口是唯一的音频宿主**：其他窗口只读 `player:state`、只发 `player:command`。
- **主窗口销毁 = 所有子窗口一起销毁**：`win.once('closed')` 里 `win = null` 后调
  `closeChildWindows()`。子窗口留着没有意义 —— 宿主没了，IPC 另一端不存在，界面还在但点哪儿都没反应；
  而且 `window-all-closed` 永远不会触发、进程也不会退。开窗入口也统一检查 `hasMainWindow()`。
- 歌词播报器默认置顶、开在主窗口**旁边**（不压住主窗口）；桌面歌词用 `showInactive()`，从不抢焦点。
- **动态操作帮助**接替了网格底部那条说明栏：宽 520，**高度由渲染层按内容量出来**
  （`help:resize`，上限工作区 85%），默认置顶、窗口内可关掉置顶；内容只有两段 ——
  「现在」（曲目/视图/选区/解析/正在输入）和手势清单。摘要由主窗口的 GridEditor
  节流 120ms 推给主进程、再转给这个窗口（它自己不读库、不持网格状态）。
  菜单「视图」「帮助」两处都能开合。
  ⚠️ **量高度要量 `.ah-inner`（内容容器），不能量 `.ah-body`**：后者是 `flex: 1` 撑满窗口的盒子，
  内容比它矮时 `scrollHeight === clientHeight` —— 等于「用窗口高算出更高的窗口高」，
  每推一次摘要就长 20px，一路长到屏幕 85%，用户看到的就是「点一下网格，帮助窗长出一大截空白」。

| 视图(V) | 详情面板 · 弹出到独立窗口 · ─── · 歌词播报器 · 桌面歌词 · 动态操作帮助 · 历史记录（`Ctrl+Shift+H`）· ─── · 小节/拍/半拍 · ─── · 放大/缩小/复位 |
| 搜索(S) | 聚焦搜索（`Ctrl+F`）· 清除搜索 |
| 选项(O) | 直接打开选项面板（`Ctrl+,`，无下拉） |
| 维护(M) | 孤儿报告 · 已归档作品… · 打开 data 目录 |
| 帮助(H) | 快捷键说明（`F1`） |

**为什么「删除作品」在文件菜单、紧接登记下面**：它作用的对象是「这份作品」，
和「登记一份新作品」是同一族操作；放在编辑里会让人误以为它只影响当前的选中内容。
而且**刻意不给加速键** —— 会丢东西的动作不该和 `Ctrl+Z` 一样顺手。

**确认框的键盘约定**（所有破坏性操作共用）：

| 元素 | 约定 |
|---|---|
| 按钮顺序 | **确定在左、取消在右**；确定键实心红（`--danger`）、略高 |
| 默认焦点 | 落在弹窗容器（`tabindex="-1"`），**不在按钮上** |
| `Enter` | **什么也不做** —— 想确认必须点，或 `Tab` 到按钮再按 |
| `Esc` | 取消（永远安全） |
| `Space` | 被弹窗吃掉（否则会穿透到播放条，弹着框开始播） |

## 4. 手势约定（同一个动作在哪儿都是一个意思）

| 操作 | 位置 | 结果 |
|---|---|---|
| 单击曲目行 | 曲目列表 | 选中这首（详情面板、波形、播放条都跟着换） |
| **单击录音版本子行** | 曲目列表 | **切到这一版**：波形重画、播放条的「原点」改的也是它（不写库、不挪顺序） |
| 双击曲目行 | 曲目列表 | 从**主录音**（顺序第一那条）开始播；没音频就唤起网易云 |
| 双击录音版本子行 | 曲目列表 | **只听这一版**（一行库都不写，不动顺序） |
| 单击 / 双击版本行 | 详情面板 | 同上两条（单击切换、双击打开「管理录音版本」） |
| **右键曲名** | 曲目列表 | 弹出这一行的菜单：播放 / 更改标题 / 添加到播放列表… / 从「某某列表」移出（只在具体列表里）/ 删除这首曲目…。**不再直接进改名** —— 改名是菜单第二项 |
| **菜单 → 添加到播放列表** | 曲目列表 | 弹窗列出所有播放列表，点一条就把这首放进去并关窗（已在其中的那条变灰写「已在其中」）；一条都没有时按钮是「新建并加入」 |
| 删除作品（文件菜单 / 曲目菜单） | 曲目列表 | 移进 `.archive`；删完停在**原位置的邻居**上（删的是最后一行就往上取，列表空了就停在空态） |
| 右键详情面板空白 | 详情面板 | 模块显隐菜单 |
| **右键「低音」行** | 网格左缘标签 **或** 那一行的网格正文 | 低音填充菜单：「从级数标记获取低音填充」（整曲扫、覆盖已有）+「每次都自动…」勾选项。**只在罗马数字视图有**；其它行的右键什么都不发生（标签层 `pointer-events: none`，两种点击都由 canvas 按 y 坐标收口） |
| **右键「和弦」行** | 网格左缘标签 **或** 那一行的网格正文 | 字母和弦菜单：「从级数标记获取字母和弦」（整曲扫、覆盖已有）+「每次都自动…」勾选项。字母和弦 / 黎曼「实际和弦」/ 和弦组成音三个视图都有这一行；转换算不出来的（如 `Cad64`）跳过并报数 |
| **右键「和弦标记」行**（斯波索宾体系视图） | 网格左缘标签 **或** 那一行的网格正文 | 斯波索宾菜单：「从级数标记获取」（可靠，自动模式只跟这条）+「从字母和弦标记获取」（先按该 tick 的调性反推级数）+「每次都自动…」勾选项。副属、那不勒斯、延伸音等没有唯一写法的跳过并报数 |
| 选中「和弦标记」格子 | 时间线面板 | 详情条显示解析出的和弦（`D7` → 属七 `G B D F`，`DTIII6/dtIII` → `D F B♭`）—— 与级数标记同一套解析 |
| 双击分隔条 | 下方面板 | 收起 / 展开面板 |
| **鼠标移到栏边界（垂直居中那 96px）** | 侧边栏 ③ 右缘 / 详情面板 ④ 左缘 | 浮出一个灰色半透明的圆角小方块（14×38，中间一个直角箭头，箭头指「点了会往哪边去」）；**点一下收起这根栏，再点展开**。识别区 22×96px，跨在边界线上 |
| **在把手上按住横向拖** | 同上 | 位移超过 4px 就不是「点击」了，转成正常调宽 —— 一个手势两种意图，不打架 |
| **拖拽栏边界** | 侧边栏右缘 / 详情面板左缘 | 改宽度；**撞到最小宽度后被夹住**（左栏的最小值是按最长文案量出来的，见 RULES §25） |
| **拖到最小宽度后继续往里挤 32px** | 同上 | 松手时收起这根栏（拖动中能反悔，拖回去就不算） |
| **在收起的栏边界上往外拖** | 同上 | 拖出 32px 就展开并继续跟着拖（不用先点开再调） |
| **点侧栏的块标题** | 侧边栏 ③ | 展开 / 收起那一块（播放列表 / 泳道方案 / 词表 / 维护，默认都展开） |
| **点设置面板左侧的 tab** | 选项面板 | 外观 / 编辑 / 播放 / 窗口：内容区平滑滚到该分组，高亮跟随滚动（scroll spy） |
| **Esc** | 选项面板 | 直接关掉；模板编辑器里有未保存文本时先弹「放弃未保存的修改？」（取消则留在面板） |
| **拖左栏 / 右栏 / 面板高度松手** | 侧边栏 / 详情栏 / 面板分隔条 | 宽度立刻写进 `userData/config.json` 的 `layout.panels`（300ms 防抖），下次启动照着摆 |
| **鼠标移到任意滚动条附近（右侧 20px 内）** | 所有滚动区 | 4px 的细条在 200ms 内展开到 20px（5 倍），可拖、可点轨道翻页；移开缩回。见 `slimscroll.ts` |
| **拖动任何窗口 / 最大化** | 主窗口与各子窗口 | 位置与大小写进 `config.json` 的 `layout.<窗口>`（400ms 防抖，关窗前再冲一次）；旧坐标落在屏幕外会被夹回来 |
| **改「外观 → 左侧边栏留白」里的四个数** | 选项面板 | 浅色 / 深色**各存一套**左右留白，改完立刻生效，并重新计算侧栏的最小宽度（同一个 36px 在深色下顺眼、浅色下常嫌宽） |
| **点播放列表里的一条** | 侧边栏 ③ | 曲目列表只显示这个列表里的曲子（搜索词仍然生效；「全部曲目」是虚拟的一条，永远等于整个曲库） |
| **Ctrl+N** | 全局 | 新建播放列表：加一条并切过去，**立刻进入改名态**（名字是「播放列表 N」且全选 —— 想改就直接打第一个字，那一个字替换原名；Enter / 点别处提交，Esc 取消但列表保留） |
| **右键播放列表 label 那一整行** | 侧边栏 ③ | 菜单：新建播放列表（Ctrl+N） |
| **右键某个播放列表项** | 侧边栏 ③ | 菜单：新建播放列表 / 重命名 / 删除播放列表（删除走确认框，曲目本身不动） |
| **点开菜单后点别处 / Esc** | 任意浮层 | 菜单关闭（RULES 第 23 条） |
| **点主 / 次时间的数字** | 播放条 ⑧ | 就地变成输入框：按当前格式写（`11.2` / `00:01:23:15` / `1:23.456`），回车把播放头跳过去，Esc 取消。写坏了什么都不做（保持原位） |
| **点时间前面那个格式图标** | 播放条 ⑧ | 换这一块的显示格式（小节 / 时间码 / 毫秒）；Alt+点 = 主次格式互换 |
| **选中无本地音频的曲目 / 外链录音版本** | 播放条 ⑧ | 出现「仅时间线」徽标：播放键驱动一条不发声的墙钟时间线，原点与播放头照常可用；不会自动和网易云同步 |
| **点「仅时间线」下的总时长** | 播放条 ⑧ | 就地改成手动总长（只影响本次会话）；进度条与文档尾部跟着变，原点偏移仍写当前录音版本 |
| 右键菜单开着时点别处 | 网格 | 菜单自动关闭（不必按 Esc） |

### 播放中单击版本

不播放时没有歧义；播放中由「选项 → 播放中单击录音版本」决定：

| 选项 | 行为 |
|---|---|
| 暂停并切过去（默认） | 先停声、再换波形，绝不出现「波形是 A、声音还是 B」 |
| 切过去接着播 | 从头播新版，适合 A/B 对比两版录音 |
| 等暂停后再切 | 不打断当前播放，暂停/播完那一刻才切 |
| 播放中先不切 | 只提示一句，什么都不动（双击仍然可试听） |

## 5. 为什么这样排（这些是刻意设计的，不是随手摆的）

| 设计 | 理由 |
|---|---|
| 标题行 26px + 菜单行 24px，两行不加分隔线 | Windows 的 `titleBarOverlay` 把系统最小化/最大化/关闭**叠在网页右上角**；标题行高度必须与 `titleBarOverlay.height` 完全相同，差 1px 按钮就比那行高一截。子窗口同理（歌词窗口 26px）。 |
| 四行栅格 `50 / 1fr / 40 / 24` | 标题、播放条、状态栏都是固定高的"仪器面板"，窗口缩放时只有中间的列表伸缩；播放条永远在同一个位置，肌肉记忆不会失效。 |
| 三列 `196 / 1fr / 344` | 左栏是导航（窄、固定），中间是工作区（吃掉全部剩余宽度，表格列不被挤），右栏固定宽（数值多，宽度一变就参差不齐）。 |
| 下方面板与列表**上下分栏**，不是浮层 | 早先是 `position: absolute` 盖在列表上（像 DAW 的 lower zone），好处是拖高度时列表不重排、滚动位置不跳；但它把列表的纵向滚动条下半截盖住了 —— 鼠标点不到、拖不动。用户 2026-11-23 明确改成上下分栏：列表的滚动条完整露在分界线上方。代价是拖高度时列表会重新布局（滚动位置仍在），行高固定所以看不出跳动。 |
| 详情面板只放摘要，逐版本字段收进模态 | 面板只有 344px，N 个版本 × 11 个字段铺下来没法看。列表里一行摘要（谁演的 · 哪年 · 多长 · 来源），改名/换文件/删/排序全在「管理录音版本」。 |
| 版本子行画树状连线 | 表达「录音**属于**作品」，不是并列的两类对象。曲目行左端有 chevron 可收起（和侧栏同一份 path，不是实心 ▾），收起状态按曲目记。 |
| 同版音质收在演奏版本下面，不单独占版本行 | 同一版录音的 flac / mp3 / ogg 是同一个「演奏版本」的不同文件；不同演奏家才是不同版本。管理窗里一个版本显示 `+N`，右栏「音源」下列出文件（换 / 移除 / 添加同版音质）。播放时父版本自己的文件优先，没绑就用第一个还在磁盘上的音质。 |
| 乐章子行嵌在母作品下，序数前缀可继续补术语 | 一部多乐章作品 = 母作品 + N 个乐章子项（`track.parent_id`）。登记时默认「第N乐章」/`III.`，光标落在末尾而不是全选 —— 用户直接往后打「行板」或「Menuetto - Allegretto」。补全合并两张表：速度 / 表情来自 `tempo_marking.json`，舞曲 / 曲式 / 体裁来自 `composition_type.json`（专业上没有「乐章术语」，见决定 57）；只做一层，乐章子项不能再登记乐章。**右键「更改标题」也走同一套前缀识别**（`movementTitlePrefix()` 从标题自认），不是只有新建乐章才能补（决定 60）。候选下拉是 Teleport 到 body 的 fixed 层（表格是滚动容器，留在行里会被裁半截），回车只有在 ↑↓ 高亮时才被补全接管，否则照常提交。 |
| 侧栏三块标题右键可搜索，搜索框内联在标题下 | 播放列表 / 泳道方案 / 词表都会越积越长，纵向滚动找一项太慢。右键标题 →「搜索…」才出现输入框（不占常驻空间），输入即按标题关键词过滤；Esc / × 收起恢复全部。只匹配标题，不做分词 / 拼音，也不搜词表条目（决定 58）。 |
| 乐章子行比录音子行再多缩进 2em（两个全角字符） | 两者都是子行，但语义不同：录音是**同一首的版本**，乐章是**另一首子曲目**。缩进差一档，扫一眼就能分开；L 形横臂同步延长（`calc(10px + 2em)`），线不会半路停在空白里。 |
| 标题 / 乐章名可以是模板，预设名补全在标题与乐章输入里 | `title.original` 保存 `%Composer} …` 这样的模板原文，列表 / 详情 / 状态栏按数据字段展开；缺数据的变量整段省略（没有 Sub-Type 就是「第二乐章 - 柔板」）。选项里能编辑预设并看到变量绿色高亮；列表与详情里的标题、乐章行内改名都提示预设名，选中后整段替换。候选列表 `ul.mov-sug` **全表只有一份**（Teleport 到 body），不要再塞回某一行的 `v-if` 里 —— 那正是曲目行补全丢失的原因。标题展示用 `white-space: pre` 保留用户手打的连续空格。详见 RULES §31、schema-log 决定 61 / 63 / 64。 |
| 启动配置放 `userData/config.json`，不放 localStorage | 「歌词 / 帮助自动打开、安全模式」都是机器本地的启动行为，不跟作品库走。选项里改立刻写盘；直接手改文件则重启生效。安全模式当前先挡住自动开子窗口，并作为以后插件加载器的硬开关。选项 → 窗口里显示路径、能直接打开文件。详见 RULES §32、schema-log 决定 62。 |
| 拍号 / 速度未标注时写「未标注」，网格与播放仍按 4/4 · 120 | 4/4 · 120 是渲染兜底，不是用户标注。详情页必须能看出「没量过」（淡色、字号与调性一致、不斜体、双击可填、留空清除）；网格与播放条照常按 4/4 · 120 工作，但这些默认值不回写档案（见 schema-log 决定 56）。 |
| 树线：悬停在线下、**选中压在线上**（方案 E） | 高亮块要么是完整一块、要么被那条线切成两半，两头都试过后选定「块在上面」：块内的线被 18% 的绿罩一层，像块自己的纹理。悬停仍让线透在上面，鼠标扫过时线是连贯的、不闪。六个候选（a/b/c/c2/e）在深浅两套主题里都比过，别凭感觉改回去。 |
| 焦点环只给 Tab 用户 | 空格是全局播放键：鼠标点完按钮焦点还在上面，随手按空格，Chromium 就会把按钮提升成 `:focus-visible`，界面里凭空长出一个绿框。所以记 `data-input`：指针按下就是 pointer（不画环），只有 Tab 才切 keyboard。 |
| 右键曲名出菜单而不是直接改名 | 一个右键只能干一件事的话，「放进播放列表」「删掉这首」就没地方放，只能先选中再从菜单栏里翻。菜单把这一行的动作收在一处，「更改标题」仍然落到原来那个行内输入框。 |
| 添加到播放列表是**弹窗选一条**，不是二级菜单 | 列表数量不固定，二级菜单一多就得滚，还挨着文件树，容易点错行。弹窗一行一个列表、点哪条就进哪条，不设「确定」——多按一次键只是多一次出错机会。 |
| 绿点 = 默认播放版本，行高亮 = 当前在看/在听的版本 | 两件事必须分开：顺序第一的那条是「点作品播放先播它」，当前高亮的那条是「波形现在画的是它」。混用一个标记会让人以为"换了版本就换了默认"。 |
| 波形只在视口内绘制（sticky + spacer） | 一小时长的音频如果按总长分配 canvas 宽度，内存和绘制都会爆。详见 `canvas-perf` skill。 |
| 深/浅色两套 tokens + 子窗口广播 | 子窗口各有独立 `<html>`，localStorage 不同步，主题必须由主进程广播；`backgroundColor` 也要跟着，否则 show 之前闪白。 |
| 子窗口开窗时**主动要**主题 | `app:theme` 只在切换时广播，子窗口比主窗口晚开就收不到那条 —— 而 `document.documentElement.dataset.theme` 是各窗口自己设的（没设 = 默认深色）。所以子窗口挂载时先 `await api.app.theme()`，主进程也在 `did-finish-load` 用 `primeChildTheme()` 补发一份。漏了这条的表现：浅色模式下帮助窗自己画成深色，只有系统画的标题栏是浅的。 |
| 系统按钮配色集中刷新 | `titleBarOverlay` 是系统画的，CSS 管不到。窗口各自在创建时拿一份 `overlayChrome()`，之后主题再变就没人管旧窗口 —— 所以 `app:theme-set` 里调 `refreshAllOverlays()` 把所有窗口（主 / 歌词 / 帮助 / 历史）一起重刷。 |

## 6. 指代约定（讨论时按这个叫）

- **「左侧栏」** = ③ 侧边栏（曲库 / 泳道方案 / 词表 / 孤儿报告）
- **「中间列表」/「那张表」/「树状图」** = ⑤ 曲目列表（含 ⑤b 录音版本子行）
- **「右侧详情」/「详情面板」** = ⑦（别再叫"侧边栏"，它和 ③ 是两块东西）
- **「下方面板」/「时间线面板」** = ⑥（DAW lower zone，不是独立窗口）
- **「播放条」** = ⑧；**「状态栏」** = ⑨
- **「歌词窗口」** = 歌词播报器；**「桌面歌词」** = 那个透明浮窗；**「时间线窗口」** = `#grid` 独立窗口
- **「管理录音版本」** = 那个模态窗口（简称"录音管理窗"也可以）
