## 1. 曲末黄字「无法播放：曲名」

**根因**（已定位）：拖到曲子末尾时 `seek()` 把 `currentTime` 设到 `duration`，
Chromium 会请求 `bytes=<文件长度>-`；即使协议层已按规范回 416，媒体栈仍会派发一次 `error` 事件 →
`state.error = audio.failed` → 播放条挂橙字。而 `play()` 里会 `load()` 自愈，所以「能播但有黄字」。

**改法**（三处，缺一不可）：

| 位置 | 改动 |
|---|---|
| `audio/store.js` `seek()` | 目标夹到 `dur - 60ms`（`EOF_GUARD_MS`），播放头**不落在 EOF 上** → 从源头不产生越界请求 |
| 同上，`seek()` 末尾 | 成功后清掉 `audio.failed`（只清这一类，真错误不动） |
| `error` 事件 | 若 `el.error.code === MEDIA_ERR_NETWORK` 且位置已在末尾 60ms 内 → **不设 error**，当 EOF 处理 |

**不做**：不改成「显示一句已到末尾」——你选了完全不出提示；真错误（文件坏了）照旧报。

## 3. 拖进度条 → 播放光标跑出视窗时翻页

- 触发源：`TransportBar` 拖进度条 → `seekAudio(ms)`；网格本来就会收到 `onFrame`。
- 判定：新增「外部 seek」识别（`currentMs` 跳变 > 500ms，且不是播放推进）→ 若播放头像素
  `x < 0` 或 `x > viewW - 96` → `setScrollLeft(x - 96)` / `x - viewW + 96`。
- **边缘留 96px**（和详情面板双击跳转、播放跟随同一套余量）。
- 独立窗口：它是从属端，位置来自 `player:state` 广播，同一段逻辑放在 GridEditor 里 → 自动生效。

## 4. 操作历史（撤销）+ 持久化

**模型**：全局一条时间线（不是每曲一条栈），每条记录 = 「这一步做完之后，那首曲子的事件全量」，
并标注它属于哪首曲子。这样「点某条回到那时」和「跨会话撤销」是同一套数据。

**为什么整份存而不是存 diff**：区间写入会裁短/拆分既有事件，逐条反做不可靠（HANDOFF 早就这么写了）。
一份快照几 KB，50 条几百 KB，不值得为省这点空间冒数据错的风险。

### 数据

`userData/undo-history.json`：

```jsonc
{ "version": 1, "items": [
  // 每首曲子第一次被改之前，先记一条 base（撤到第一步之前要用）
  { "id": "h1", "at": 1792, "kind": "base", "trackId": "trk-x", "title": "神鹿谣",
    "analysisId": "an-x", "label": null, "events": [...] },
  { "id": "h2", "at": 1793, "kind": "step", "trackId": "trk-x", "title": "神鹿谣",
    "analysisId": "an-x", "label": { "key": "grid.act.write", "vars": { "value": "V7" } }, "events": [...] }
] }
```

### 行为

| 动作 | 结果 |
|---|---|
| 任何写库（写入/删除/移动/改长度/粘贴/填充/标记） | 追加一条 step；`items` 超过「运行期上限」就丢最旧 |
| `Ctrl+Z` | **只撤当前曲目**：游标退到该曲上一条（step 或 base），恢复它的状态 |
| `Ctrl+Shift+Z` | **全局撤销一步**：撤掉全局游标那条（属于别的曲目就自动切过去） |
| `Ctrl+Y` | **重做当前曲目**：游标前进到该曲下一条（该曲游标之后没有新操作时才有） |
| `Ctrl+Shift+Y` | **全局重做一步**：全局游标前进一条 |
| 历史窗口点第 N 条 | 恢复第 N 条状态；如果属于别的曲子，主窗口自动切到那首并选中 |

**游标模型**：每首曲子记一个 `cursorSeq`（已应用到的步序号），另有全局 `globalCursorSeq`。
新的写库操作发生时，**当前曲目游标之后的历史项全部丢弃**（经典 undo 语义），新项追加到末尾。
| 关软件 | 只把**最近 50 条**写盘（全局算），下次启动读回来 |

### 历史窗口（新窗口 `#history`）

- 宽 520（和帮助窗一致），高按内容自适应、上限同帮助窗。
- 列表一项一行：`12:03 · 神鹿谣 · 写入「V7」`；当前所处的条目高亮；点条目跳过去。
- 列表下面是「清空历史」按钮（清空后就不能再撤了，弹确认）。

### 设置项（选项 → 网格手感附近）

| 键 | 含义 | 默认 |
|---|---|---|
| `ma-undo-limit` | 运行期最多保留多少步（空 / 0 = 无限） | 无限 |
| `ma-undo-persist` | 关闭软件时写盘最近多少条（全局） | 50 |

### 「默认」拍板

- 历史窗口入口：菜单「视图 → 历史记录」+ 快捷键 `Ctrl+Shift+H`。
- 「撤销」本身**不记一条**（历史就是状态序列，撤销 = 指针往回走）。
- 跨会话恢复时，如果某条记录对应的曲子已被删 → 跳过并清掉该条（不报错）。

## 5. 工作区（布局记录与快速调用）

### 记什么（你选的「再加主题/泳道/缩放」）

- 主窗口：位置 + 大小 + 是否最大化
- 面板：高度 + 开关；左右栏宽度
- 界面缩放、主题模式（深/浅/跟随/定时）
- 网格：泳道方案、缩放倍数、格单位
- 子窗口：独立时间线（是否开 + 位置大小）、动态操作帮助（是否开 + 位置）、歌词播报器（是否开 + 位置 + 是否置顶）

**不记**：当前选中的曲目（否则一换工作区就跳曲，会打断你）、播放位置。

### 存哪

`userData/workspaces.json`：

```jsonc
{ "version": 1, "last": { ...当前布局... }, "named": { "编辑用": {...}, "听歌用": {...} } }
```

窗口位置必须由主进程读写（渲染层拿不到），所以存主进程这份文件。

### 入口：**顶级菜单「工作区(W)」，排在「选项(O)」左边**

- 保存当前布局为…（弹输入名字，重名就问是否覆盖）
- 分隔线 + 已保存的工作区列表（点一下即应用，当前那个打勾）
- 管理…（重命名 / 删除）
- 分隔线 + 还原上次布局

### 启动

`last` 在 `createWindow` 时应用（窗口 bounds），渲染层字段在挂载时应用；`named` 只在手动切换时应用。

## 7. 验收（冒烟新增，预计 +14~18 条）

1. 曲末：`seek(dur+1000)` 后 `error === null`；再 `seek(dur-5000)` 能播
2. 帮助窗：启动后自动开；宽度 520；高度 = 内容高（±2）；屏幕矮时封顶且内部滚动
3. 翻页：拖进度条到远处 → 播放头在视窗内、左侧余量 ≈ 96px（时间线面板 + 独立窗口各一条）
4. 历史：写一步 → 出现在列表；点旧条目 → 数据回到那步；Ctrl+Z 只撤当前曲；Ctrl+Shift+Z 跨曲撤且自动切曲
5. 持久化：写 3 步 → 关软件（模拟：重建 GridEditor + 重读主进程历史）→ 还能撤
6. 工作区：保存一份 → 改布局 → 应用 → 完全还原（窗口 bounds 用主进程读回比对）

## 8. 明确不做

- 不做「撤销的 diff/压缩」以外的优化（整份快照已经够用）
- 不把录音层/曲目元数据放进撤销（撤销只管分析事件）
- 不做撤销的 diff/压缩（整份快照，可靠性优先）
