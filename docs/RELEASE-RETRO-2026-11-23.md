# 一次「从代码仓库到能装的软件」的复盘（2026-11-23）

> 这份文档写给**不熟悉开发流程**的人看：今天到底做了什么、踩了哪些坑、为什么会花掉那么多时间。
> 没有任何指责的意思 —— 这些坑大多不是「谁写错了」，而是「工具和现实世界的规矩不熟」。

---

## 一、一句话总结

今天做了三件事：把「music-atlas」改名 **miyako** 并整理成一个能公开看的仓库；
给它打出了第一版**能安装、能双击运行**的 Windows 安装包；在 GitHub 上发布了第一个 Release，
顺便用 GitHub 的机器打出了 macOS 和 Linux 的版本。

中间绊了 **14 个跟头**，每个都已经修好，并且写成了「以后不会再犯」的规则。

## 三、踩过的坑（通俗版）

### 打包类

**1. 打包像「把整个衣柜塞进快递箱」**
electron-builder 打包时会把项目里的 `node_modules`（几千个开发用的小包）**全部**塞进安装包，
结果安装包 200MB、其中一大半是根本用不上的东西。
→ 改成「先全部排除，再只放回运行真正需要的三个」。安装包从 200MB 降到 126MB。

**2. 打包顺手把「别人的作品」也带走了**
`assets/` 目录里放着我本机的音乐母带、歌词、专辑封面。`.gitignore` 只管住了 git，
管不住打包程序 —— 结果这些文件被一起塞进了安装包。
→ 在打包配置里加了排除规则（母带、歌词、专辑封面一律不进包）。

**3. 装好之后「数据该写哪儿」是个坑**
原来打包版把曲库数据库写在**安装目录**里。但装到 Program Files 后那个目录是只读的，
而且每次升级都会被覆盖 —— 等于用户的曲库随时可能消失。
→ 改成：第一次启动时，把随安装包带来的「词表种子」复制一份到
`%APPDATA%\miyako\data`（用户自己的地盘），之后一直读写那一份。

**4. 打包程序想「自己去发版」**
electron-builder 看到项目里有 GitHub 仓库，就想顺手把构建结果发布到 GitHub。
本地没问题（我有登录态），但 GitHub 的自动构建机器上没有凭据，直接报错退出。
→ 打包命令加上「不要发布，只打包」。

### 自动构建（CI）类

**5. 公开仓库里没有我的曲库，一条测试就红了**
有条规定是「档案格式必须合规」，这条测试的前提是「曲库里得有东西」。
公开仓库**故意**不带我的个人曲库（隐私），于是三个平台的测试同时红。
→ 改成：曲库为空时这组测试**跳过**并说明原因；本地有曲库时照常检查。

**6. Windows 的自动机器默认说「另一种话」**
我写的上传步骤用了 bash 的数组语法，但 GitHub 的 Windows 机器默认用 PowerShell 执行，
一跑就语法错误。
→ 给这一步显式指定用 bash。

### 网络与工具类

**7. GitHub CLI 根本没装**
我一直以为装好了，其实机器上没有。后来下了一个「免安装版」放在项目里。
→ 顺带发现它的「网页登录」接口被公司的网络代理挡成 502，只能手工取设备码。

**8. 代理像门卫，对 GitHub 只放行一种方式**
这台机器的网络必须走一个本地代理（127.0.0.1:11415），但代理对
`github.com` 的 CONNECT 请求一律回 502。git 自带的加密方式又和代理合不来。
→ 最终解法：换用 OpenSSL 方式直连 + 绕过代理变量。这条已经写进项目记忆，以后照抄。

**9. 下载速度只有 60KB/s**
打包要下载 Electron 运行时（约 110MB），按这速度要半小时。
→ 改用本机已经装好的那份运行时，不重复下载。

**10. 268MB 的产物「下载到本地再上传」是最蠢的路线**
本来想把 macOS 的构建产物下载回本地，再上传到 Release 页面。
但按 60KB/s，一个多小时才下了一半 —— 而且下完还要再上传一遍。
→ 改成让 GitHub 的机器**直接**把产物传到 Release 页（仓库里的工作流加了一个参数）。

**11. 打包好的程序「一启动就没」**
在这台开发机的终端里，有个环境变量会让 Electron 变成「纯 Node 模式」，
于是打包好的程序一启动就打印一句看不懂的英文然后退出。
→ 不是软件 bug，是这台机器的环境问题；启动时把这个变量清掉就正常了。
（顺带也验证出：数据库迁移、词表加载、界面都正常。）

### 代码与文案类

**12. 模板编辑器里光标和字对不齐**
这个最有意思：模板里「变量」那段原本是**加粗**显示的。等宽字体下粗体和常规一样宽，
所以看不出来；可 v0.97 把默认字体换成了无衬线之后，粗体明显更宽 ——
那一段之后的字全都右移了，而光标还停在「正常宽度」的位置。
→ 变量只改颜色、不改字重；同时把两层文字的字体度量（字重、字距、滚动条占位）逐项对齐。

**13. 乐章后面加了字，补全反而不弹**
补全逻辑拿的是「乐章标题的整段」去匹配词表。我已经写了「第二乐章 柔板」再接着打 `Al`，
整段就变成「柔板Al」，一条词都对不上，于是界面安安静静什么都不弹。
→ 先按整段匹配（多词术语需要），匹配不上就退回「光标前那一小段」再试。

**14. 一个英文键插错了地方**
新加的中文提示语，在编辑时把英文版也插进了中文区，导致英文界面缺这个键。
→ 单测当场抓住（i18n 键集必须四语言一致），改回正确位置。

## 四、为什么花了那么多 token？

先解释一下 **token 是什么**：模型一次能"读"的字数。大致可以理解成
「我替你通读了多少页材料」。文件越大，读得越多。

这次的消耗主要来自这几处：

1. **改代码前必须先读代码**
   这个项目的核心文件很大：`src/main/index.ts` 有 674KB、`App.vue` 有 308KB。
   每次要动某块功能，都得先定位、再读那一段 —— 光是这两个文件就够读很久。

2. **每改一次都要跑完整验证**
   这个项目的冒烟测试有 **602 条断言**，跑一轮约 5 分钟；
   单元测试 401 条。也就是说：改一行 → 编译 → 跑 602 条断言 → 看有没有红。
   这一轮就是 5 分钟起步，改十几轮就是一个多小时。

3. **失败要定位，不能猜**
   打包闪退、CI 三连红、下载卡住……每一次都要写一个小探针去重现、
   读日志、读 CI 输出、再改再验证。定位 14 个坑，大半时间花在这。

4. **反复的构建与上传**
   打包一轮 2–3 分钟；上传 240MB 的安装包到 GitHub 又是一轮 3 分钟；
   CI 上传 macOS 的 268MB 还要十几分钟。

5. **一行改动常常牵一片**
   改一句界面文案，要同步中文 / 繁体 / 英文 / 日文 / 香港版五份词典，
   再重新生成繁体词典、跑 i18n 一致性测试。

6. **还有「等」**
   机器在下载、在打包、在上传、在跑测试，这些时间我只能等 —— 等待本身不消耗 token，
   但等完还要重新读一遍结果，等于又一轮。

**一句话总结**：不是「一次做完」，而是「做 14 次错，每次都要从头验证」。
换成人的工时，大概相当于一个下午 + 一个晚上的返工。

## 五、现在的状态

> 这是 2026-11-23 当天的快照。mac 的 ad-hoc 签名、三平台的 better-sqlite3 预编译包、Windows 的自签名，以仓库里的 `electron-builder.yml` 和 README「下载」一节为准，不要按下面这张表里的「没签名 / 右键打开」去放行一个完全没签名的 arm64 包。

| 东西 | 状态 |
|---|---|
| 公开仓库 | https://github.com/elifia-flora/miyako —— 已公开，单条提交，历史干净 |
| 协议 | Apache-2.0，版权人 elifia-flora，**以后一直保持** |
| Windows | 安装包 + 免安装版，**已实测能启动** |
| macOS | Apple Silicon 的 dmg / zip 已上传；**没签名**，第一次要「右键 → 打开」 |
| Linux | AppImage 已上传，双击即用 |
| Intel Mac | 还没有（CI 的 mac 机器是 M 系列），想要就加一个 x64 构建 |
| 图标 | mac 版还是 Electron 默认图标（有 .ico，没有 .icns） |
| 签名 / 公证 | 没做（需要 Apple 开发者账号，一年 99 美元） |

### 以后要改代码时，记住这几条

1. 改完先跑 `npm test`（401 条，1 秒）和 `npm run smoke`（602 条，5 分钟）；
2. 打包用 `npm run dist:win`；macOS / Linux 用 Actions，别在 Windows 上硬来；
3. 推送用 `git -c http.sslBackend=openssl push`（这台机器的代理会挡默认方式）；
4. 发布到公开仓库要走「发布线」那条分支，别把带个人曲库的历史推上去；
5. 新增界面文案 = 五个语言文件都要改（单测会检查键集一致）。

## 六、给不熟悉开发的人的三句话

1. **今天的成果**：一个公开的、带 Apache-2.0 协议的仓库，加上三个平台能装的软件包，
   别人可以直接下载试用（Windows 一路绿灯，macOS / Linux 是 GitHub 的机器打的，不需要你有 Mac）。
2. **代价**：返工了 14 次，原因是「打包 / 网络 / 自动构建」这些环节都有各自的规矩，
   第一次做总要撞几次才知道。
3. **往后**：坑都记在 `docs/RULES.md` 和项目记忆里了，下次同类问题会快得多。
