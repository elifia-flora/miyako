# 输入手感：和弦标记补全的决定记录

> 这份文档只回答一个问题：**敲下去之后，为什么第一个候选是这个**。
>
> 代码位置：`src/shared/cellsug.js`（字母和弦 / 级数）、`src/shared/sposobin.js`（斯波索宾）、
> 词表 `data/vocab/chord-symbols.json`；界面（`views/GridEditor.vue`）只负责把候选画出来。
> 单测在 `tests/cellsug.test.mjs`、`tests/sposobin.test.mjs`，冒烟里有一组真实的输入序列。

---

## 0. 两条流程规矩

**① 关键字冲突必须先问，不要自己拍**（2026-11-08 用户点名）。
一个字母/数字要在两个含义之间选，或者新的缩写会**减少**某个已有输入的产出 —— 这就是冲突。
例：`a` 既要「增和弦 aug」又要「add6 / add9」；`t` 既要「主和弦本身」又要「最常接的六级」。
遇到这种：**把两边的代价说清楚、给选项、等答复**，别猜。判据很简单：
> 这次改动会不会让某个原先能出候选的输入，变少 / 变差？会 → 先问。

**② 每次改完补一条决策记录**（第 3 节，最新在上）。
第 1 节「现行规则」是结论，第 3 节是过程。只更新结论 = 下次又要把同样的问题想一遍，
而且会忘掉「当初为什么不选另一条路」。

## 1. 现行规则

### 1.1 字母和弦的分层

```
exact（后缀或别名完全相等）
  > 前缀（字母泳道的「查询后面紧跟数字」优先）
    > 模糊：连续子串 > 顺序子序列 > 字符都在（乱序）
```
- 同一档里「首字符就对上的」优先：打 `Vs6` 先给 `Vsub6`，再给 `V7sub6`。
- 模糊匹配**不连续、可乱序**：`C76` / `C67` / `C6` 都能找到 `C7sub6`。
- 单字符查询只对**数字**开模糊（`V6 → V7sub6`）；单个字母不开 ——
  否则 `iis` 会被 `7sus4` 的 s 拉出一屏噪音。
- 候选上限：字母 8 条（**单字母缩写例外，见 1.2**）、斯波索宾 20 条
  （多到能看见整族，又不至于盖住格子）。
- 别名只参与匹配、**不复制候选行**：打 `C7b9` 得到的是词表里的 `C7♭9`。

### 1.2 单字母缩写（只有 `j` 和 `a`）

| 输入 | 候选（顺序即下面的档位顺序） |
|---|---|
| `Cj` | `Cmaj7` → `Cmaj9` → `Cmaj13` → `Cmaj♯11` → `Cmaj13(♯11)` → `Cmaj11` |
| `Ca` | **`Cadd2` → `Cadd4` → `Cadd6` → `Cadd9`** → `Caug` → 上面那一串 maj |

- 为什么 `j`：它就是 `maj` 里的那个 j，敲完音名手指还停在右半边，不用挪到 a。
- 为什么 `a`：`aug` 的首字母；**但 `a` 的第一顺位给了 add 族** ——
  用户 2026-11-08 复盘：「aug 不如 add 系列常用」，所以是 **add → aug → maj**。
- 只有这两个字母走缩写；`Cm` / `Cs` / `Cd` 仍走前缀匹配。
- 每一档用正则取（`^add` / `^aug` / `^maj`），不写死后缀列表 —— 词表里加东西时候选自己跟上。
- **不受 8 条上限截断**：`Ca` 一共 11 条，缩写本来就是「一次看全、再用方向键挑」的场景。
  候选框 `max-height` 因此从 180px 抬到 264px（11 行）。

### 1.3 冲突登记（同一个键的两个意思）

| 键 | 争用的含义 | 现在的裁决 | 代价 / 备注 |
|---|---|---|---|
| `o` | 减三和弦的别名（`Co` = Cdim）↔ 省略音关键字 `omit` | 关键字前面必须是数字或括号（`C13o`） | `Co` / `Vo` 仍然是减三；`C13o` 才给 `C13omit` / `C13no` |
| `a` | `aug` ↔ `add6 / add9 / add2 / add4` | **add 族 → aug → maj 族**（2026-11-08 二次调整） | 缩写不再受 8 条限制，11 条一屏给全；`a2/a4/a6/a9` 仍然单独可用 |
| `j` | `maj` 家族 | 全给它 | 没有第二个含义，零代价 |
| `m` | 小三（`Cm`）↔ `maj`（`Cmaj7`） | 前缀命中里「紧跟数字」优先 | `Cm` → `m7b5 / m7 / m9` 先出，maj 排后面 |
| `s` | `sus2 / sus4 / sub6`（字母）↔ 升号（**级数前**） | 按泳道分开 | 字母泳道不许用 `s` 当升号：`b` 会和音名 B 打架 |
| `b` | 降号（级数前）↔ 半减七提示（`ban / bj`）↔ `m7b5` 里的 `b5` | 按位置分 | `Bb` 里的 b 是音名的一部分，不是降号 |
| `6` | 转位（级数）↔ 加六音（字母） | 按泳道分开 | 级数里 `6` 永远是转位，要加音写 `add6` |
| `t` / `T` | 主和弦本身 ↔ 六级 `tsVI` | 完全相等 → 六级 → 主和弦的七和弦 | 见 2026-11-07 那条教训 |
| `v` / `vi` | 六级 ↔ 导七（`DVII`） | 六级 → 导七四转位 → 重导 | 本体系里 `v` 不是「属」，用户打它就是在找六级/导七 |
| `h` | 半减七提示 ↔ 什么都不做 | 级数泳道里 `h` 专给半减七 | 后面可跟转位数字：`iih42` |

### 1.4 三条泳道不能混

| 泳道 | 候选来源 | 铁律 |
|---|---|---|
| 级数（roman） | 词表 `qualities` 的后缀 | 绝不出绝对和弦（`C7`）；裸 `ii` / `vii` 永远第一 |
| 字母和弦（letter） | 词表 `letters × accidentals × qualities` | 绝不出 `V7` 这类相对写法 |
| 斯波索宾 | `sposobin.js` 自己一套 | `C` / `K` → `K46`，与级数无关 |

### 1.5 省略音（`no5` / `omit3`）

写好和弦之后可以「减掉一个音」：`C13no11`、`C9omit5`、`Cmaj7no3`、`C7♯9no9`（`V9(omit5)` 也认）。

- 按 **几音** 匹配（不是按音高）：`no3` 去掉三音、`no9` 去掉那个九音（♭9 / ♯9 都算 9）。
- **只写关键字不给数字 = 什么都不省略**。这样补全插进来的 `C13omit` 不会立刻变成解析失败。
  `parsed.omits` 只记**真的删掉了东西**的那些（`C13no11` 是空的），详情栏照着它念「省略十一音」。
- 补全：打 `C13o` → `C13omit` / `C13no`；打 `C13n` → 只给 `C13no`。
  **触发条件窄**：关键字前面必须是数字或括号 —— `Co` 是最常见的减三和弦写法（`o` 是 dim 的别名），
  不能被这条抢走；`Vo` 同理。

### 1.6 斯波索宾的排序闸门（`rankByPrefix`）

```
⓪  六级特例：打 t / ts / v / vi → 源族三和弦 → tsVI 整族 → 导七与重导（仅 v / vi）→ 源族七和弦
⓪' 只打 i / ii → 二级族 → 六级族 → 其余（三级 / 七级）
①  完全相等永远第一（打 S56 先给 S56）
②  大小写打反但字母一致的（小调里敲 S 也先给 s… 但只到这一档，见 ③）
③  常用表 COMMON_MAJOR / COMMON_MINOR（s5 要让 sII56 赢）
④  字面上以输入开头的
⑤  同族配对 SIBLINGS（DD56 之后紧跟 DDVII56、D7 之后紧跟 DVII7）
⑥  首字母出现得越靠前越好
⑦  前缀短 → 全串短 → 字母序（只为了保证结果稳定）
```
v0.74 起 `t / s / d / k` 走「首字母完全相同（含大小写）」过滤 —— 大小写是**语义**，不是大小写不敏感。

## 3. 决策记录（最新在上）

### 2026-11-08 详情栏文案：和弦名 + 升十一 + 省略N音；字母泳道的 69 不带括号

**改了什么**：
1. 有七音时**按最高的自然延伸音给和弦起名**：`Cmaj13(♯11)` → 「大十三和弦 · 升十一 · 原位」，
   不再写「大七 · 加 9 音 · 加 13 音 · ♯11 音」。名字里已经含的 9 / 13 不再单念。
   `C7` → 属七和弦、`C9` → 属九和弦、`Am9` → 小九和弦、`C6/9` → 六九和弦。
2. 变化音改念「**升十一 / 降九**」，不再是「♯11 音」。
3. 省略音写进详情栏：`C9omit5` → 「属九和弦 · 省略五音 · 原位」。
   只有**真的删掉了东西**才说（`C13no11` 本来没有十一音，就不念）。
4. 字母泳道的六九和弦写成 `C69`（`C6/9` / `C(6/9)` 也都认），级数泳道仍是 `V(6/9)`。

**为什么**：用户原话 —— 懂乐理的人看「大十三和弦 · 升十一」就知道是什么；
不懂乐理的人看「加 9 音 · 加 13 音」照样一头雾水。两头都不讨好，不如只留名字。
69 那条同理：字母和弦没有数字低音，括号纯属多余。

**代价**：`V7` 的说法从「小七」变成「属七和弦」（更准，但和旧断言不同）；
`numeral()` 只管 1–9 的转位序号，念 11 / 13 会被夹成「九」，于是另写了 `extNumeral()`。

### 2026-11-08 13 隐含九音 + 省略音 `no` / `omit`

**改了什么**：`13` 也隐含九音（`Cmaj13(♯11)` = C–E–G–B–D–F♯–A，`C13` = C–E–G–B♭–D–A）；
新增省略音 `no5` / `omit3`（按「几音」删，♭9/♯9 都算 9）；
补全 `C13o` → `C13omit` / `C13no`、`C13n` → `C13no`。
**为什么**：用户指出 `maj13(♯11)` 少了九音 —— 和 `11` 那条是同一个直觉：数字越大越全。
省略音则是给「真有不要的音」留出口（`C13no11` 这种）。
**代价**：`C13` 从 5 个音变 6 个音；`o` 有两条含义（减三别名 / omit），靠「关键字前面必须是数字或括号」分开。
**实现要点**：`parsed.omits` 存的是级数数组；解析器版本升到 v10，启动时会重算全库 `parsed`。

### 2026-11-08 `a` 的顺序改成 add → aug → maj

**改了什么**：`Ca` 的前五条从「aug + maj」改成 `Cadd2 / Cadd4 / Cadd6 / Cadd9 / Caug`，后面才是 maj 族；共 11 条，不再被 8 条上限截断（候选框 180 → 264px）。
**为什么**：用户复盘「aug 不如 add 系列常用」，而 `a` 的第一顺位被 aug 白占着。
**代价**：候选框变高（一屏 11 行）。`a2 / a4 / a6 / a9` 的单点入口不受影响。

### 2026-11-08 11 隐含九音（`C11` = 7 + 9 + 11）

**改了什么**：数字分支里 `11` 会额外补一个 9 音（隐含，不占「重复延伸音」的名额）。
`C11 → C–E–G–B♭–D–F`、`Cmaj11 → C–E–G–B–D–F`；`Cadd11` 仍然只有十一音。
**为什么**：用户给的判据 ——「想要单独的十一音，有 `add11` 的」。写了 `11` 就是完整的十一和弦。
**顺带确认**：`maj9` 本来就带七音（`C–E–G–B–D`），字母与级数两边都是；`maj9` 不缺东西。
**未动**：`13` 现在只带七音（`Cmaj13 = C–E–G–B–A`，不含 9）。要不要也带九音**先问过再改** ——
这条按同一套直觉应该带，但一封十三和弦里塞 9 是另一种音响，别自己拍。

### 2026-11-08 小重属 `dd` 给一条「字面」候选

**改了什么**：斯波索宾泳道里，输入以两个小写 `d` 开头时，**第一项就是打的字面**（`dd` / `dd56`…），
右侧用警告色写「极罕见：小重属（小属的小属）」；后面照常接 `DD` 族的补全。
**为什么**：小属的小属在体系里几乎不出现，候选池里没有这一族；硬猜会造假候选，
但用户偶尔真要写它 —— 给个字面入口 + 一句警告，比「什么都不给」和「猜一个」都好。
**判据必须区分大小写**：大写 `DD` 是正常重属，不受影响。

### 2026-11-08 补上 `add2` / `add4`

**改了什么**：词表加 `add2`（加二音）、`add4`（加四音），紧挨着 `add6`。
**为什么**：用户打 `Ca2` 一个候选都没有 —— 解析器早就支持 `add2`（`C–D–E–G`，夹在三音下面），
词表里却漏了这条，于是「能解析但补不出来」。
**代价**：`Cadd` 前缀列表多两条；`C` 裸根音的候选不变（这两条不是 `primary`）。
**备注**：`add11` / `add13` 解析器也认，但词表里仍然没有 —— 没人要过，先不加。

### 2026-11-08 前缀命中里「紧跟数字」的优先

**改了什么**：同样的前缀命中，查询后面紧跟数字的（`m7` / `m9` / `m7b5`）排在还是字母的（`maj7…`）前面。
**为什么**：maj 家族从 1 条变成 6 条之后，打 `Cm` 的 8 条上限被 `maj7…maj11` 占满，
`Cm7` / `Cm9` 直接消失 —— **加词表时踩出来的回归**。
**理由**：`m` 后面跟数字是同一个词的延续（`m7`），跟字母往往是另一个词（`maj`）。
**代价**：几乎没有（只有 `m` 开头这一种情况有变化）。

### 2026-11-08 字母和弦的单字母缩写 `j` / `a`

**改了什么**：`Cj` → maj 家族六条；`Ca` → `Caug` 打头 + 同一串 maj。
**为什么**：用户实际敲键盘时，`Cmaj13` 要按四个键才到 maj 家族；`j` 是 `maj` 里的那个字母，
离音名最近。`a` 是 `aug` 的首字母。
**代价（用户已确认接受）**：`Ca` 不再列 `add6 / add9 / add2 / add4`。
所幸 `a6 / a9 / a2 / a4` 都还能出 add 系列，`cadd` 也能整族列出，所以「没那么坏」。
**取舍**：没有把 add 系列塞到 maj 之后 —— 1 + 6 + 4 会超过 8 条上限，反而把 `Cmaj11` 挤掉。

### 2026-11-07 `t` 恢复「完全相等优先」——一次改错的教训

**改错了什么**：v0.72 把「打 `t` 第一条给 `tsVI`」当成用户要求写进代码。
**事实**：用户原话是记错了，v0.75 改回 `t / t6 / t46` → 六级 → `t7 / t56 / t34 / t2`。
**教训（已升级成 §0 那条规矩）**：**新要求与已定规矩冲突时先问，别自己拍**。
这次的错法很典型 —— 用户一句「t 的第一条应该是 tsVI」听着像需求，实际和「完全相等永远第一」
这条老规矩打架；我选了新话、没提冲突，结果白改一版。

### 2026-11-07 大小写严格服从输入 + 越界附注

**改了什么**：`t / s / d / k` 之后按「首字母含大小写完全相同」过滤；
小调里打大写 `S` 时右侧附注用橙黄「共晓小调少见的大下属」；大调里打小写 `s` 用绿色「和声大调的小下属」；
Dorian 不提示（两边都正常）。
**为什么**：用户在小调里敲大写 `S`，补出来的却是小写 `s` —— 大小写在这套体系里是**语义**（大 / 小三和弦）。
**代价**：候选池分成两套，同屏只出现一套。

### 2026-11-07 `vi` 追加导七与重导；候选上限提到 20

**改了什么**：打 `v` / `vi` 时，六级之后接 `DVII7 → DVII56 → DVII34 → DVII2 → DDVII → …`。
**为什么**：用户打 `v` 想的是「导音上的和弦」，而导三和弦在功能上远不如导七常用。
上限 8 → 20 是为了让这一串真的能看见。

### 2026-11-07 斯波索宾改子序列匹配 + 六级特例 + `i` 模式次序

**改了什么**：匹配从「前缀开头」放宽到**子序列**（不连续、不分大小写）；
`t / ts / v / vi` 走六级特例；只打 `i` / `ii` 时按「二级族 → 六级族 → 其它」三段排；
候选右侧带罗马数字提示。
**为什么**：原来打 `i` / `v` **一个候选都不出**，可这两个字母正是 `tsVI` / `dtIII` / `DVII` 里出现的位置。

### 2026-11-05 同族配对（`DD56` → `DDVII56`）

**改了什么**：`SIBLINGS` 表让「重属 ⇄ 重导」「属七 ⇄ 导七」在候选里前后脚出现。
**为什么**：它们是同一件事的两种写法，转位一一对应；打 `DD56` 时第二条就该是 `DDVII56`。

### 2026-11-05 S 组常用优先 + 完全相等第一；七和弦转位改 `56 / 34`

**改了什么**：`COMMON_MAJOR / COMMON_MINOR` 常用表排在「字面前缀」之前，但完全相等永远第一；
七和弦转位按苏俄习惯写 `56 / 34`（不是 `65 / 43`）。
**为什么**：打 `s5` 时 `sII56` 字面上不是前缀、却远比 `s56` 常用；转位写法是用户逐条口述的规则。

### 2026-11-05 离调改斜杠写法

**改了什么**：`DTIII6/dtIII`；重属用 `DD` / `DDVII` 系列。
**为什么**：用户按斯波索宾体系的实际写法定的，不是笔误。

### 2026-11-04 ~ 05 级数泳道的几条底子

- 裸 `ii` / `vii` 永远第一，半减七只在 `h / half / b / ban / bj` 显式触发（不做调式推断）。
- 双拼 / 拼音前缀只用于**级数前**：降 `b / j / jiang / jl`、升 `s / sheng / u / ug`。
  字母和弦仍用 `C# / Cb` —— `b` 会和音名 B 打架。
- `sub6` = 六音替五音，`V7sub6 = G–B–E–F`；`(6/9)` 在级数里必须带括号（`6` 是转位）。
- `7b9` 这类别名参与匹配，但候选只出词表里的规范写法（`7♭9`）。

## 4. 已知取舍 / 待定

- **`13` 已经带九音**（2026-11-08 定），但**不带十一音** —— 十一音和大三度打架，爵士里默认省略；
  真要就写 `add11`。
- **`C7sus4` 仍念「小七 · 挂四」**：命名表只管 大七 / 属七 / 小七 三族（`chordTypeName`），
  挂留、减七、半减七、增和弦走原来的说法。要给挂留也起名（属七挂四）得先加 12 个文案键，没做。
- **候选上限 8（字母）**：`Ca` 的 11 条是唯一例外。要再往里加东西，先算一下这 11 条还放不放得下。
- **单字符模糊只对数字开放**：想对字母也开，得先解决「`Cd` 会不会炸出一屏」的问题。
